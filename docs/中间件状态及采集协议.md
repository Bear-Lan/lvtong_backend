# 中间件状态及采集接入（2026-11-07）

本说明优先于旧文档中“status全1无效”的历史假设。用户本轮确认DEVICE前后段可按动作状态/在线位理解；bit20含义未知，暂不参与显示和业务判断。

## DEVICE

`$NTRMC,DEVICE,<动作状态十六进制>,<在线位十六进制>`

- bit0～19依次为红灯、黄灯、绿灯、补光、急停、预约、栏杆、地感、光幕、200光源、160光源、200光闸、160光闸、200内锁、160内锁、声音报警、前语音、后语音、前显示屏、后显示屏。
- 所有动作字段只取前段；后段独立解析为在线信息，1在线、0离线。后段全1是合法值，不替代动作字。
- bit18/19显示原始动作位0/1；在进一步确认语义前不宣称具体文案已显示。
- 单字段兼容报文只提供动作信息，在线未知；不把未知等同离线。
- 原始字段保留stateRaw、onlineRaw；cmdRaw是前段兼容别名，raw保留旧末段取值兼容。新业务应使用明确字段。
- 未变化的DEVICE最多每秒更新一次缓存及推送，最近反馈超过5秒标记过期；这与设备自身在线位分别展示。
- `/api/device/status`返回sensors，含bit、state、online、status；过期时state/online返回null。`devices`保留原有驱动实例列表兼容，不能将驱动初始化成功当成传感器在线证明。

## 停止X光

- 顶部急停、PLC面板急停开启，均使用停止X光接口，只发送`$MDRMC,1,xraycap=false`，不停止道闸、相机、几何采集或距离调度器。
- 保持现有流程，不新增启扫锁定、自动恢复或停止其他设备的动作。实体bit4继续作为反馈及复位弹窗依据；复位不隐式发送xraycap=true。
- 发送失败返回错误；发送成功只表示UDP命令已提交，不伪造光源/急停状态反馈。
- 用户询问既有复位行为后，本轮保留urgentstop=false再xraycap=false的命令顺序；不再伪造急停位已清零，真实状态等待DEVICE反馈。

## 几何采集及启扫参数

- 提供`send_geomcap(True/False)`，组包为`$MDRMC,1,geomcap=true/false`。
- 用户已确认：预约受理只准备本轮采集，检测放行时与线扫一起发送geomcap=true；正常由中间件自动停止，取消或重置时软件发送geomcap=false。取消后或上一轮遗留的延迟任务不能重新开启几何采集。急停X光不停止几何采集。LAZ读取、示范回退及3D显示继续独立工作。
- 用户进一步确认xraycap第二参数继续使用预约红线距车头的长度，第三参数由预约界面大小车型决定（big→large，small→small）；保留现有映射，不新增独立图大小选项。

## 辐射计数值

- 已观测格式`$NTRMC,RADIOMETER,<数值>`独立解析、推送radiometer_status，并由`/api/device/radiometer-status`回放。
- 只接受有限浮点数，保留0读数。用户要求不加单位；返回unit=null，不换算、不设置报警阈值，页面只显示原始数值。
- 数值10秒未更新显示过期，与bit20含义和DEVICE在线判断分开处理。

## 验证边界

业务启停与急停回归全部使用模拟发送器/禁止网络套接字。现场验证仅被动读取已运行服务与组播反馈，不通过受理、放行或检测接口测试，也不启动200/160射线。
