# 相机主子码流与预约来源

## 相机

- 照片采集五路：车顶 cam_road、车头 cam_head、车尾 cam_lane、球机 cam_ptz、预约 cam_booking。
- 视频通过现有 WHEP 路径 cam6/cam2/cam1/cam5/cam4 读取子码流（视频通道1为102）；周界 cam3 保持原配置。
- 手动拍照调用登录接口 `POST /api/capture/camera/<device_id>`，后端直读所选相机主码流（视频通道1为101），返回原分辨率 JPEG dataUrl。主码流失败直接提示，不退回预览截图。
- 原自动车头/车尾/车顶采集也固定主码流，JPEG质量默认95，可用 CAPTURE_JPEG_QUALITY 覆盖。
- 保留设备视频通道号，忽略旧 streamType 对拍照/预览的影响。完整 rtsp_channel/rtspChannel 优先，其次 channelId/channel_id；抓拍兼容 HIK_RTSP_CHANNEL 旧环境配置的视频通道。
- 车顶照片继续裁去左侧1/3、保留全高。采集前后共用车道占用保护，切换相机、关闭弹窗或占用期间的迟到照片丢弃。手动照片确认前不广播为其他类别。

## 预约来源

- 检测中系统页面点击预约：页面提示“当前处于检测流程中，请提交或重置后再预约”，不发起预约动作；API `source=ui` 同样拦截。
- 硬件 DEVICE bit5 上升沿及 `source=plc`：恢复原来的预约记时、停止空闲招揽、红灯、落杆、step2语音及LED流程。检测中也执行，保留待受理反馈，当前检测不结束、不弹预约窗口；硬件反馈不弹页面点击专用提示。
- 内部硬件 book_button 转发也调用同一原流程；页面空闲预约仍走原流程。
