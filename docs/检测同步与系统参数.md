# 检测同步与系统参数（2026-11-13）

本轮仅迁移、开发和验证本机，不同步现场。现场升级时必须把数据库迁移、后端和前端作为同一版本更新。

## 当前检测共享

同一后端对应一条车道、一份当前检测会话，保存在 `inspection_session` 表。登录后 GET `/api/inspection-session/current` 恢复当前预约、检测步骤、占用、照片、表单、备注、查验选择及点云。登录的 WebSocket 连接加入 `inspection_sessions` 房间接收后续快照。切换终端或刷新只恢复数据，不重发受理、抬杆、采集或光机命令。

登录页的匿名连接在登录成功后重新握手认证，切换账号会重建连接，退出时断开；重复调用同一凭据的connect不会新建第二条连接。后端连接日志和connect_ack包含检测同步认证结果，便于定位“已连接但未订阅共享会话”。浏览器验收包含先打开真实登录页再登录，不能仅用预填token代替。

PC 检测途中，Pad 使用同一后端登录即可继续拍照；新增货物照和证据照追加到已有列表，PC 实时收到。无需操作权锁，按用户约定由一个终端操作。表单修改按字段保存，350ms 合并请求；相同字段的旧版本冲突返回409，断网未保存内容保留在当前页面并显示未同步，可点重试。换设备前确认顶部显示“已同步”；未上传的本机照片不能在别的设备恢复。

图片在共享时从临时缓存转为持久文件，点云以共享JSON文件保留以供旋转查看。数据库记录的3D雷达图片是视图截图。提交带 `inspection_session_id`，唯一约束防止同一会话生成两条记录；提交成功后自动重置并通知各端清空。旧会话请求不能修改新一辆车。后端重启可恢复业务数据，不会自动重发设备命令或恢复未完成的采集任务。

## 本机数据库迁移

先备份，再在后端目录执行：

```powershell
venv\Scripts\python.exe tools/migrate_inspection_session.py
venv\Scripts\python.exe tools/migrate_system_config.py
```

两个工具限定为本机 `gcis`。本轮已执行，原21条记录保留，旧雷达字段内容删除。新字段为 `appointment_radar_image_path`（预约雷达图）、`radar_3d_image_path`（点云3D视图截图），替换旧 `radar_side_image_path`、`radar_top_image_path`、`radar_head_image_path`。上传、预览和历史详情已统一使用新字段。

## 语音与预约

业务空闲和语音1资格独立。合法VARMC持续到达时才允许语音1，默认5秒未收到视为过期；不检查旧20米阈值或VMRMC目标数。受理后抑制语音1，光幕由开变关后恢复其资格，但仍处于检测流程，直到提交或重置。只有初次收到光幕关闭状态、缺少光幕字段都不能当作关闭沿。语音1按原配置间隔重复，前后两侧发送，LED跟随语音步骤。

已移除旧7～9米黄灯规则及5～7米、3～5米的独立LED步骤规则。启动时只迁移config里这三条旧规则，其他地址、距离和自定义配置保留；调度器读取旧JSON也会忽略这三条。光幕开关时间由真实DEVICE沿记录，不由距离覆盖；关闭不切黄灯、不复位，车尾拍照锚点逻辑保留。

检测中页面预约、后端 `/booking/open`、`/booking/btn-press` 及实体预约键都只提示“当前处于检测流程中”，不记待预约、不红灯落杆、不播语音2、不打断已恢复的语音1。

## config 参数表

首次启动把原文件和环境变量默认值写入 `config`，已有记录不覆盖。随后数据库为参数来源。45项参数覆盖中间件URL、相机映射、点云尺度、组播收发网卡/地址/端口、命令模板、语音LED映射、重复/播放保护时长、调度规则/距离、净空帧数、车尾拍照偏移和轮询超时。DB连接、证书和图片存储根目录不在该表中。

保存仅写数据库，不下发命令；**后端重启时整批生效**，避免检测途中切换配置。`main.py` 在初始化设备和调度器前启用参数。修改环境变量不会覆盖已存的配置项。

管理员（role=0/admin）登录后维护：

```http
GET /api/config
Authorization: Bearer <登录token>
```

返回每项 key/value/revision/activeValue/pendingRestart。使用读到的revision提交，防止覆盖他人的编辑：

```http
PATCH /api/config
Authorization: Bearer <登录token>
Content-Type: application/json

{"values":{"voice.varmcFreshSec":5},"revisions":{"voice.varmcFreshSec":0}}
```

示例revision须替换为实际读取值。复杂项必须提交完整JSON对象，先GET再修改需要的部分。

| key | 实际用途 |
| --- | --- |
| middleware.RADAR_HEAD_URL | 预约雷达图 |
| middleware.RADAR_POINT_CLOUD_URL | LAZ实时拉取 |
| middleware.BODY_CAMERA_IMAGE_URL | 车身连续拉图的实际URL；BODY_IMAGE_URL是兼容配置，改车身地址时两项保持一致 |
| middleware.TRANSPARENT_IMAGE_URL | 透视连续拉图的实际URL；XRAY_IMAGE_URL是兼容配置，两项保持一致 |
| transport.MCAST_GROUP / MCAST_PORT / MCAST_IFACE_IP / MCAST_RECV_IFACE_IP | 组播目的地、发送及接收网卡 |
| commands.templates / commands.prefix | 逻辑命令映射到下发报文，包含camcap/geomcap/xraycap和PLC/LED/语音 |
| scheduler.workflow | 距离阈值、PLC规则、净空27米连续5帧默认值、车尾偏移5米默认值 |
| voice.announce / voice.varmcFreshSec / voice.playbackDurationSec | 编号方向、重复间隔、VARMC新鲜度、共用播放保护 |
| led.steps | 语音业务步骤对应DISPLAY编号 |
| capture.pollIntervalSec / maxPollSec / connectTimeoutSec / readTimeoutSec | 采集轮询频率及超时 |

命令模板校验业务占位符、禁止逗号和换行。距离、端口、地址、编号、时长等会先校验，整批保存失败则全部回滚。正常采集结束不发false、车道占用阻止拍照等既有逻辑保留。
