# 抓拍与车道占用

2026-11-09：车道占用时统一拦截拍照，使用现有调度器的占用判定，不增加检测放行后的新占用规则。

- 受理后、自动抬杆前，有有效目标且距离低于配置的净空距离（现场21米），从首个占用帧开始阻止拍照。页面仍连续3帧确认后显示占用，避免防抖期间抢拍。
- 已确认占用后，连续3帧正常才解除拍照拦截；无目标不会解除已确认的占用。
- 车头、车顶的距离自动抓拍和光幕触发的车尾抓拍统一拦截。被阻止的阈值不标为已拍；恢复后仍须满足原距离条件，不在驶离区间后补拍。
- 手动单张和批量采集也检查占用；被阻止时接口返回409及明确提示。上传已有照片、浏览视频不属于相机采集入口。
- 线扫车身采集的camcap=true、车身拉图启动、轮询请求和图像推送均检查占用。已经在途的RTSP/HTTP图像，如果期间发生占用或重置，则丢弃，不覆盖当前预览；恢复后可重新获取。
- 放行仍按原正常连续5帧逻辑，放行后不把车辆正常进入21米以内改判为占用。否则会错误阻止正常过车的车顶照。
- 不更改灯、闸、语音、LED、几何采集和X光机控制动作。

自动距离配置见`config/scheduler_config.json`：车头26.5～28.5米、车顶20～22.5米，车身图在23～28米进入轮询。线扫实际启采仍在正常抬杆时发送camcap=true。

隔离验证见`tests/test_capture_lane_guard.py`，包括首帧拦截、3帧恢复、自动/手动入口、车尾、线扫、迟到帧丢弃和其他动作不变。
