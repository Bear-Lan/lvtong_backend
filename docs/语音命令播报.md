# 自动语音命令播报

## 2026-11-13 操作台提示循环

底部“审核”改为“提示”，列表目前只有9号“前方超限车辆倒车，请注意避让”。鉴权 `GET /api/device/voice/prompt` 获取选项与全局循环状态；`POST` 的 `{"action":"start","step":9}` 启动，`{"action":"stop"}` 停止。重复启动幂等，只有一个后台任务；刷新或多个终端同步读取该任务状态，不各自创建定时发送。循环有效时图标闪烁，包括每轮停顿及等待业务语音期间；发送失败结束循环并显示错误。

每轮前后侧均用VOICE9。收到本轮起播/结束反馈后停顿 `prompt_gap_sec`（默认2秒）再发下一轮；现场播放位可能滞留或交替，不能可靠关联本轮命令，因此本轮超过 `prompt_clip_sec`（默认10秒）后也进入2秒停顿，避免循环永久卡住。时长应覆盖配置的整条语音；此兜底仅适用于本循环最后发送的提示，被新业务语音抢占后仍须等其保护释放，不修改空闲语音的真实播放保护。两项可在 `config/voice_announce.json` 调整，时长范围1～120秒、停顿0.5～30秒；修改后下次启动生效。不能把估计等待当作硬件播放完成回执。

提示循环首次由人工选择可抢占空闲；后续重复若被新业务语音抢占，会等业务播放保护释放再恢复，不再次抢断它。提示整个循环包含停顿期间均阻止空闲VOICE1抢播，停止循环仍保留当前条的播放保护。用户明确同意：再次点击立即停止后续循环和图标闪烁，当前这一条自然播完；不发送尚未确认的STOP协议，也不调用检测复位、设备停止或X光接口。停止和实际派发串行，停止响应成功后旧任务不能再发下一条。后端重启默认不自动恢复人工循环，状态实例编号改变使页面重新同步。

此前空闲播报规则已由最新版覆盖：合法VARMC独立触发，光幕1→0只恢复语音招揽；具体优先级和反馈缺失处理见 `README_启动.md`。

自动播报通过现有 `send_mdrmc` 向组播中间件发送以下命令，由中间件驱动语音串口设备：

```text
$MDRMC,1,frontvoiceannounce=VOICE1
$MDRMC,1,backvoiceannounce=VOICE1
```

不直接打开 COM 端口，不向海康发送音频。人工对讲及其通道锁保持独立。

## 现场映射

编辑 `config/voice_announce.json`，无需重启即可读取新的映射。已按用户提供的编号表配置为前后两边均播报、业务编号与 VOICE 编号一一对应。

- `targets`：`["front"]`、`["back"]` 或 `["front", "back"]`。
- `steps`：键为语音预置编号 1～9，值必须为已经确认的 `VOICE1`～`VOICE9`。现有自动流程只触发 1～5；6～9 仅提供预置，不新增自动触发动作。
- `repeat_interval_sec`：空闲招揽命令的起始间隔，默认 10 秒，范围 1～3600 秒。须根据设备是否自带循环和音频长度确认间隔。

| 业务步骤 | 当前业务文案（不代表设备录音编号） |
| --- | --- |
| 1 | 绿通车辆，按键检测 |
| 2 | 申请已接收，请原地等待 |
| 3 | 申请已受理，请等待放行 |
| 4 | 待检车辆，请通行 |
| 5 | 检测中，请勿跟车 |
| 6 | 请打开车门 |
| 7 | 请勿遮挡车厢 |
| 8 | 拍摄完成，请关好车门 |
| 9 | 前方超限车辆倒车，请注意避让 |

前后目标分别发送单命令包，不同时调用 HTTP。缺失映射、无效编号或非法目标时拒绝发送；不会回退到海康或自动选择编号。已发送 UDP 不代表设备收到或语音播放完毕；`stop_speak` 仅停止后续本机派发。

用户补充的中间件状态位为 bit16 前语音、bit17 后语音：0 未播报、1 播报中；与 bit15 声音报警独立。

**2026-11-05 19:25/19:28 现场实测纠正：语音状态实际变化在 DEVICE 前字段（当前代码命名 cmdRaw），后字段始终 `001fffff`。** 从 `.88.253` 分别发送前后 VOICE1，来源 `.0.100` 的反馈前字段依次为 `000080c2 → 000180c2 → 000080c2`、`000080c2 → 000280c2 → 000080c2`；再用生产入口 `speak_step(1)` 前后一起发，反馈为 `000080c2 → 000380c2 → 000080c2`。说明命令有对应中间件播报状态响应，不代表已验证声学输出。

DEVICE 经现场 WLAN `192.168.0.102` 到达，以太网 `.88.253` 未收到该路状态。解析已按实测修正为读取前字段 bit16/17；接收配置 `MCAST_RECV_IFACE_IP` 可与发送配置 `MCAST_IFACE_IP` 分离，未设置时沿用后者。现场分别配置为 `.0.102` 和 `.88.253`。不能将后字段恒定的高位1当作播放成功。

WS `plc_status` 与 `/api/device/plc-status` 缓存返回 `frontVoiceAnnounceStatus` / `backVoiceAnnounceStatus`。Pad 的「PLC设备状态控制」面板只读展示前后语音“播报中 / 未播报”；尚无反馈或 WS 断线时显示“待反馈”，不把发命令当成设备正在播放。该状态没有 VOICE 编号或请求标识，不能仅凭一次 0 状态认定某条命令已经播完。本次验收仍以正确业务时机提交正确组播命令为准。

预约按键和随后 `/booking/open` 共用本轮 step2 的一次派发结果，防止串行到达重复播报；`announceCommandSent` 表示命令是否成功提交，`announceDone` 不虚报设备播放完成。

## 预约按钮

实体预约键为 DEVICE 前字段 bit5（零起算，`ST_APPOINTMENT`，掩码 `0x20`），解析为 `bookingStatus`，0→1 触发。页面按钮通过 `/api/booking/btn-press` 调用相同业务处理：记录待处理预约及时间、红灯、落杆、前后 VOICE2；仅空闲时打开预约弹窗，检测中只显示待处理提示。长按键期间其他位变化不重复触发，打开弹窗不重复派发 VOICE2。

对应动作已用隔离测试覆盖实体/页面 × 空闲/检测中四种组合，未向现场注入预约报文，也未调用现场受理、放行或检测接口。实体按键的真实电气变化仍需现场实际按键验收。

## 无硬件测试

在后端项目目录运行：

```powershell
python -m unittest discover -s tests -v
```

测试使用模拟 UDP 发送器并禁止创建网络套接字，不调用检测、PLC、栏杆或 X 光接口。

实际 VOICE 编号和前后两边播报已由用户确认。空闲招揽按软件配置周期发送，默认 10 秒；若现场设备单次命令自带循环，需根据实际行为调整。现场部署保留原文件备份；不要通过受理、放行或启动检测来测试语音，这些业务路径包含设备联动。
