# H.265 相机在 Pad 浏览器播放

六路相机均按 H.265 输入设计，摄像头本身的编码参数不作修改。抓拍使用的 OpenCV 解码与实时视频是两条不同链路；实时视频必须先转为浏览器可兼容的 H.264。

```text
相机 RTSP → MediaMTX camN_input → FFmpeg H.264 → MediaMTX camN → WHEP → Pad
```

入口仍为 `/mtx/cam1/whep`～`/mtx/cam6/whep`。每一路只有在被观看时启动一个 FFmpeg，同一路的多个读者共享转码。最后一位读者离开10秒后停止编码，再过10秒释放相机拉流。断流由 MediaMTX 按需重启子进程。

后端启动时根据原有 `mediamtx.local.yml` 和数据库相机配置，生成不入库的 `mediamtx.runtime.yml`。生成文件含相机凭据，不能提交 Git。FFmpeg 的命令只访问本机输入路径，不带相机密码。MediaMTX/FFmpeg 诊断输出保存在后端 `logs/mediamtx.log`，达到5MB时在下次启动轮换一次。

安装 `requirements.txt`，或设置 `FFMPEG_EXE` 指向可信的 FFmpeg 文件。默认从 PATH 查找，再使用 `imageio-ffmpeg` 包内的 FFmpeg。默认 H.264 Constrained Baseline、yuv420p、无B帧、1秒关键帧、宽度最多1280、15fps，仅转视频；人工对讲仍使用独立链路。

环境变量：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| VIDEO_ENCODER | auto | 实际试编码验证 NVIDIA 驱动；成功用 h264_nvenc，失败回退 libx264 |
| VIDEO_MAX_WIDTH | 1280 | 输出最大宽度，320～3840偶数 |
| VIDEO_FPS | 15 | 输出帧率，1～30 |
| FFMPEG_EXE | 自动定位 | 自定义 FFmpeg 可执行文件 |
| VIDEO_WEBRTC_HOSTS | 沿用模板 | 现场 LAN/Tailscale IPv4，以逗号分隔；设置后仅广告这些IPv4，并开启UDP/TCP 8189 |

配置显式IPv4时同步把 UDP 负载上限降为1180字节，避免 Tailscale MTU1280 下大包分片导致 ICE 能连接但视频帧无法到达。

现场 P2000 的当前驱动只支持 NVENC API 8.1，包内 FFmpeg 7.1 要求12.2，因此当前自动回退CPU；本次不升级显卡驱动。编码能力以真实试编码为准，不能仅因 FFmpeg 列出了 h264_nvenc 就判定可用。

播放器停止/切换时关闭 PeerConnection、取消待完成请求，并 DELETE WHEP 会话；删除地址保留同源代理前缀。状态“playing”以视频实际开始播放为准。

测试只允许拉取相机预览和模拟流，不调用受理、放行、检测、PLC或X光业务接口。
